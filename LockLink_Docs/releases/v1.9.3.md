# LockLink v1.9.3

Source version **1.9.3+193**, including app, firmware diagnostics, Settings footer,
and all three iOS widget configurations. This records local source changes on
30 September 2026; it does not establish a published release.

## Pairing controls and connection errors

- Get setup/sharing code, Check pairing, pairing options, close-window actions,
  and connected-home refresh no longer disable/re-enable during each read-only
  background poll. Actual commands, queued commands, and connection loss still
  disable device actions. Commands remain deliberate and are never replayed.
- Connection failures are red on Home, Terminal, and smart-home screens. The
  dark theme now has accessible red error colors; initial checking stays neutral.
- Each ecosystem guide has a button to open its home app. Google on Android
  can hand the current QR to Play Services' documented Matter commissioning
  picker, with a Google Home app-launch fallback. Other routes launch the
  installed app and retain Add Accessory / Add Device instructions.
- Missing or blocked apps show a recoverable error. Apple Home requires iOS;
  desktop/web give phone setup guidance. iOS schemes are best-effort and cannot
  guarantee a specific accessory page. No cloud account linking or HomeKit
  entitlement is introduced. Pairing secrets still hide on background.
- Corrected About Door Release: it is a Matter door lock. Unlock starts the
  two-second output; Lock stops it early. Output state is not door-position proof.

## Pairing mechanism repairs

- Compare against the homes in the reply that opened the pairing window. A
  different phone's change between STATUS and PAIR ADD cannot falsely confirm
  this setup. Reboots require a fresh code, and an existing legacy pairing is
  not presented as a newly completed home.
- Firmware hides provisional AddNOC fabrics from connected-home snapshots until
  CommissioningComplete commits them. A pending home that rolls back cannot
  appear as a successful pairing or change the sharing-window home baseline.
- USB PAIR reopens expired first-home windows with supported BLE advertising,
  matching the QR payload. ArduinoMatter's default BLE memory release is
  disabled so Bluetooth setup remains available after removing the last home.
  This retains BLE RAM; actual memory headroom and radio behavior need board tests.
  Additional-home commissioning remains on the local network.
- Retained window ownership/expiration checks, shared temporary codes, bounded
  fabric capacity, stable removal IDs, failsafe mutation guards, and code hiding
  on connection loss/background/window closure. Removing homes still preserves
  Wi-Fi, other homes, and the LockLink app key.
