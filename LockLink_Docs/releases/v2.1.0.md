# LockLink v2.1.0

Source version **2.1.0+210** across Flutter, firmware, Settings and all three
iOS widget configurations. This release improves recovery from intermittent
ESP32-C3 connection failures and reduces firmware memory pressure.

## Changes

- Home shows Connecting/Reconnecting during bounded recovery attempts. It
  retries a failed status read after one second, then two seconds, then every
  five seconds. Device actions remain disabled until a fresh response succeeds.
- Terminal keeps the latest 16 device log lines instead of 64, saving 8,064
  bytes of fixed RAM. Existing cursor/gap and per-line truncation behavior stays
  compatible. Home and Terminal poll only while their page and app are active.
- Wi-Fi uses two static RX buffers and four dynamic RX/TX buffers, with receive
  aggregation disabled for this memory budget. Matter continues managing saved
  networks and reconnection; BLE commissioning remains available.
- Terminal reserves history serialization once, checks allocation/write
  failures before executing a command, and streams JSON through a fixed
  256-byte buffer. An incomplete socket write ends the response.
- USB/authenticated `STATUS` reports minimum heap, largest free block and failed
  allocation counts. Unlock and pairing commands are never automatically replayed.
- `pubspec.yaml` is the release version source. One sync command updates the
  platform metadata and current guide references. Manual Release derives its
  tag automatically, rejects an existing release before building, and checks
  again before publication.

## Verification

The repaired firmware completed **376/376 requests over 316.6 seconds**, including
Home polling, challenges, repeated authenticated Terminal reads, an idle gap
and idle-client recovery. There were zero request timeouts or allocation
failures. Final free heap was 23,284 bytes and reported minimum heap 4,964 bytes;
the earlier history-only image reached 244 bytes and recorded 14 allocation
failures. The user confirmed automatic recovery on cold launch and return from
the background. See the [diagnosis and measurements](../CONNECTION_DIAGNOSIS_2026-10-01.md).

Those hardware results were collected before the version-only bump. Seven
native firmware suites, 74 Flutter tests and Flutter analysis passed for the
repair. Hardware testing used USB power with the relay disconnected. Fresh
Matter commissioning, router loss/rejoin, physical relay behavior and iOS
build/install need separate checks. Commanded release state does not verify
physical door position.

For the version bump, release metadata validation and the v2.1.0 C3 build pass.
The release guard accepts `v2.1.0` and rejects stale `v2.0.1`/`v2.0.0` tags.
Nine focused version-tooling tests pass, including synchronization, preserved
historical records, draft-note rejection and mocked published/missing release
responses. Workflow lint passes. The manual release workflow has not been run
for this change; new APK/IPA artifacts have not been built or published.

## Updating

Build matching v2.1.0 app and ESP32-C3 firmware. Ordinary application updates
preserve Wi-Fi and Matter storage; avoid the combined factory image for updates.
See [C3 installation](../ESP32_C3_SETUP.md). Manual Release derives `v2.1.0`
from the source version without a tag input; publication requires its validation
and platform builds. See [version synchronization](../../README.md#version-updates).

Previous behavior and validation remain documented in the
[v2.0.1 release notes](v2.0.1.md).
