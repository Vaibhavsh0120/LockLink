# LockLink v2.0.1

Source version **2.0.1+201** across Flutter, firmware, Settings and all three
iOS widget configurations. This patch packages the current ESP32-C3 Super Mini
relay and app response improvements.

## Included behavior

- GPIO4 stays HIGH at idle and pulses LOW for one second. Lock ends the pulse
  early; the active-LOW GPIO8 blue LED follows the release timer.
- The powered controller disables Wi-Fi modem sleep after connection and
  reconnect, reducing receive delays at the cost of higher power consumption.
- The ready foreground app prepares a single-use challenge so a tap with a
  fresh preparation sends the signed unlock command immediately. Expired or
  unavailable preparations fetch a fresh challenge. Background, Settings and
  offline transitions invalidate prepared access; unlock commands are never
  automatically retried.
- Fresh app installs use `192.168.0.112` and the requested default signing key
  described in the [app guide](../../LockLink_App/README.md). Saved settings take
  priority. Firmware Wi-Fi and signing credentials remain separately configured;
  the requested default signing key is intentionally included in app builds.
- Current setup guides and manual-release examples use `v2.0.1`. The previous
  [v2.0.0 notes](v2.0.0.md) retain the C3 migration and earlier validation details.

## Verification

Release metadata matches **2.0.1+201**; the release guard accepts `v2.0.1` and
rejects the stale `v2.0.0` tag. Workflow syntax and current documentation links
pass. The Android release APK identifies itself as version **2.0.1**, build **201**.
Configured and public C3 builds pass image verification, and the Flutter web
release builds successfully. The preceding behavior revision passed Flutter
analysis, 72 app tests and six native firmware suites; this version bump changes
no control logic.

The user confirmed Unlock/Lock operation on the C3. Actual latency after the
Wi-Fi and app changes still needs a hardware timing check. iOS builds, native
widget behavior and Apple/Google/Alexa control require their platform/device
checks. Commanded release state does not verify physical door position.

## Updating

Install the v2.0.1 app and use the normal PlatformIO upload for the updated
firmware. Ordinary uploads preserve Matter/Wi-Fi NVS; the combined factory
image erases it. See [C3 installation](../ESP32_C3_SETUP.md) and
[relay setup](../RELAY_SETUP.md).
