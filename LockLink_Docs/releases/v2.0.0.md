# LockLink v2.0.0

Source version **2.0.0+200** across Flutter, firmware, Settings and all iOS widget
configurations. This release moves the hardware from ESP32-S3 N16R8 to
**ESP32-C3 Super Mini**, while retaining the authenticated local app and Matter
connected-home management from v1.9.3.

## Changes

- One `esp32-c3-supermini` PlatformIO environment: RISC-V, 4 MB flash, no PSRAM,
  DIO at 40 MHz, native USB Serial/JTAG. The SDK remains pinned to pioarduino
  55.03.312-1 / Arduino-ESP32 3.3.12.
- GPIO4 is active HIGH: OFF at startup/idle, ON for **one second** on accepted
  Unlock. Lock stops it early; duplicates do not extend it. One shared duration
  drives local API responses, state expiry and the ESP timer cutoff.
- The active-LOW GPIO8 blue LED follows the same timer, including stop, reset
  and failed timer arming. Removed the S3 RGB driver and loop-based indicator
  updates. Both outputs switch OFF without waiting for network processing.
- Startup sets hardware output latches before enabling GPIO drivers; this also
  fixes Arduino 3 ignoring a pre-`pinMode` `digitalWrite`. GPIO checks reject
  old S3 pins and relay use of C3 boot straps.
- Relay mode is the default. An absent/invalid private app key keeps real relay
  commands unarmed for both app and Matter. Existing private credentials are
  preserved; hardware macros in the local ignored configuration use C3 pins.
- A 4 MB partition layout reserves 64 KB NVS for Matter/Wi-Fi, one app slot
  and crash dumps. USB updates only; no second OTA slot. Factory dependencies
  now include bootloader/partition images, preventing stale factory packages
  after a partition-only rebuild. CI verifies C3/4 MB image headers, partition
  contents and factory-image placement before uploading artifacts.
- Fresh app installs default to `192.168.0.112`. Existing saved addresses are
  retained. The router still assigns the board's actual address.
- Removed the public fallback app key. Fresh installs keep relay release
  disabled until a key is saved, while still showing device status. Terminal
  and widget setup explain missing credentials; widget storage is cleared
  instead of retaining stale access. Existing saved/private keys are preserved.
- Release publication now requires reusable C3 firmware checks and workflow
  validation as well as both mobile builds. Android uses Java 17; actionlint
  is pinned and its download checksum verified. Firmware artifacts reject
  private configuration, and image verification also enforces DIO at 40 MHz.
  The release guard checks the README and release-note version and rejects
  stale or missing notes instead of silently publishing a generic description.
- Updated current setup, wiring, recovery, widget and terminal documentation;
  older release notes remain historical.

## Migration

Follow [C3 installation](../ESP32_C3_SETUP.md) and [relay wiring](../RELAY_SETUP.md).
Use a GPIO4 pulldown to hold the active-HIGH relay OFF during reset, before
firmware runs. The new C3 needs new Matter commissioning; the S3's accessory
identity and pairings do not automatically transfer. An old GPIO test sketch
uses another partition layout, so erase the C3 once with the relay/load
disconnected before the first installation. Preserve NVS on subsequent updates.
Never publish private configuration or firmware built with private credentials.

one-second expiry without a main loop, early stop, duplicate commands, stale
timer callbacks, failed timer arming, reset exclusion, millisecond wraparound,
and no GPIO4 writes in LED mode. The new factory checker was exercised against
a stale partition image and rejected it before regeneration.
Image guards also rejected wrong chip, flash size, flash mode/frequency,
stale factory contents and factory writes into NVS. Release guards rejected
stale README/release-note versions. The installation guide distinguishes normal
uploads that preserve NVS from factory images that erase saved pairings.

Physical C3 flashing, power/relay tests, BLE/Wi-Fi commissioning, peak runtime
heap, Apple/Google/Alexa control, and iOS/Xcode builds remain unverified on this
Windows run. Complete the installation guide's physical checks before permanent
installation. Commanded release state does not verify the physical door state.
